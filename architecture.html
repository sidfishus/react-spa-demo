1. System overview

Single-region deployment: one Rust process serves the API and production SPA. Private catch data stays on the client (OPFS + Google Drive sync). Public/social features hit the server.

Monolithic Axum router. Handlers → repositories → SQLite. No ORM. Writes batched via BatchWriter; reads use deadpool-sqlite pools.

4. Background tasks

5. Key data flows

Public catch share

sequenceDiagram
    actor User
    participant UI as Svelte UI
    participant Worker as localSqlDb worker
    participant API as Rust API
    participant FS as CatchImages FS
    participant Mod as image_moderator.py
    participant FB as Facebook

    User->>UI: Mark catch for public share
    Note over Worker: PeriodicSync (writer, 5s)
    Worker->>API: POST /api/catchimages/upload
    API->>FS: Store full + thumb
    API->>API: Enqueue pending_blob_backup
    Worker->>API: POST /api/publiccatch
    API->>API: status = pending moderation

    loop every 5 min
        Mod->>API: GET pending catches + classify
        Mod->>API: POST /api/internal/publiccatch/moderate
    end

    API->>FB: Auto-post on approval
    User->>UI: View in public feed
    UI->>API: GET /api/publiccatch/*

Private data sync (Google Drive)

sequenceDiagram
    participant Writer as Writer device
    participant Drive as Google Drive
    participant Reader as Reader device
    participant OPFS_W as OPFS SQLite (writer)
    participant OPFS_R as OPFS SQLite (reader)

    Writer->>OPFS_W: Local CRUD (all private data)
    loop every 5s
        Writer->>OPFS_W: Export incremental DB zip
        Writer->>Drive: Upload blob (writer lock)
    end
    loop every 5s
        Reader->>Drive: Check for new blobs
        Reader->>OPFS_R: Import / merge
    end
    Note over Writer,Reader: Server never stores private catch data

7. Technology stack

LayerTechnologies
FrontendSvelte 5, TypeScript, Vite 7, PWA/Workbox, sqlite-wasm, Leaflet, Luxon
BackendRust, Tokio, Axum, rusqlite, deadpool-sqlite, JWT, reqwest
Backgroundsystemd timers, Python (NudeNet), Rust backup CLI
Storage6× SQLite, filesystem images, OPFS (client), GCS (backups)
AuthGoogle OAuth PKCE, HTTP-only refresh cookies, JWT bearer
SyncGoogle Drive API (client-side, writer/reader model)
DeployBare metal, TLS, no Docker Compose
